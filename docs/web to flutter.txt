تحويل تطبيق ويب (رياكت) الى تطبيق موبايل فلاتر

دليل تحويل مشاريع الويب إلى Flutter (منهجية الوكيل الذكي)

هذا الدليل مخصص لمساعدة وكلاء الذكاء الاصطناعي (AI Agents) في تحويل مشاريع الويب (مثل React/Next.js) إلى تطبيقات Flutter بنفس الشكل والوظائف ومنطق العمل.


---

1. مرحلة التحليل والاستكشاف (Analysis Phase)

يجب على الوكيل فهم بنية المشروع الحالي قبل البدء في كتابة أي كود Flutter:

تحليل المسارات (Routing): فحص ملفات مثل App.tsx أو routes.ts لتحديد عدد الصفحات (Screens) وكيفية التنقل بينها.

تحليل البيانات (Data Models): البحث عن ملفات types أو interfaces لفهم هيكل الكائنات (Objects).

تحليل الحالة (State Management): تحديد كيفية إدارة البيانات (React Context, Redux, or Hooks) ومكان تخزينها.

تحليل الواجهة (UI/UX): فحص ملفات CSS (Tailwind) لتحديد الألوان الأساسية، الخطوط، والمسافات (Spacing/Padding).


2. إعداد بيئة Flutter (Setup Phase)

إنشاء المشروع: استخدام الأمر flutter create مع تحديد الـ Organization والـ Package Name.

تجهيز المجلدات: إنشاء هيكل مجلدات احترافي داخل lib:

models/: لتعريف كائنات البيانات.

providers/: لإدارة الحالة (State Management).

screens/: لصفحات التطبيق الكاملة.

widgets/: للمكونات الصغيرة القابلة لإعادة الاستخدام.


إضافة التبعيات (Dependencies): إضافة المكتبات المكافئة لمشروع الويب في pubspec.yaml:

provider أو riverpod: بديل لـ Context API.

lucide_icons أو font_awesome_flutter: للأيقونات.

intl: لتنسيق الأرقام والتواريخ.

url_launcher: للتعامل مع الروابط والمكالمات.



3. بناء هيكل البيانات والمنطق (Core Logic)

تحويل النماذج: ترجمة TypeScript Interfaces إلى Dart Classes مع وظيفة copyWith لتسهيل التحديث.

إدارة الحالة: إنشاء ChangeNotifier (في حال استخدام Provider) يحتوي على:

قائمة البيانات (List).

الوظائف الأساسية (CRUD operations).

منطق الحسابات (مثل إجمالي المبيعات أو الفلترة).



4. تنفيذ الواجهة (UI Implementation)

دعم اللغة والاتجاهات (RTL Support):

تفعيل localizationsDelegates في MaterialApp.

ضبط الـ locale والـ supportedLocales لدعم العربية بشكل صحيح.


السمة العامة (Theme): تعريف ColorScheme يطابق ألوان Tailwind المستخدمة في الويب (مثل Emerald, Slate, etc.).

المكونات الصغيرة (Widgets): البدء بتحويل المكونات المتكررة (مثل الـ Cards والـ Badges) لضمان اتساق التصميم.

الصفحات (Screens): بناء الصفحات واحدة تلو الأخرى مع التركيز على:

SafeArea: لضمان عدم تداخل المحتوى مع نوتش الهاتف.

SingleChildScrollView: لضمان استجابة الواجهة للشاشات الصغيرة.

Form و TextFormField: لعمليات الإدخال مع التحقق (Validation).



5. الربط والتحقق (Integration & Verification)

التنقل (Navigation): ربط الصفحات ببعضها باستخدام Navigator أو الـ BottomNavigationBar.

اختبار المنطق: التأكد من أن إضافة أو تعديل البيانات في صفحة ينعكس فوراً في الصفحات الأخرى (مثل التقارير وقائمة الطلبات).

تجربة المستخدم (UX): إضافة تأثيرات بسيطة مثل CircularProgressIndicator عند الحفظ أو AlertDialog عند الحذف لمحاكاة تجربة تطبيقات الموبايل الأصلية.



---

نصائح إضافية للوكيل:

التزم بالبساطة: لا تبالغ في تعقيد الهيكل إذا كان المشروع الأصلي بسيطاً.

التنسيق: استخدم intl لضمان ظهور العملات والتواريخ باللغة العربية وبشكل منسق.

الاستمرارية: تأكد من أن أسماء المتغيرات والوظائف في Flutter تعكس نفس مسمياتها في مشروع الويب لسهولة المراجعة.
